# Work WBS Skill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `$work-wbs`, which creates a versioned LUKUKU-standard XLSX and PDF schedule from verified project work items without inventing scope, dates, owners, effort, or completion.

**Architecture:** A validated JSON manifest is the single rendering input. The local history MCP stores immutable per-document schedule snapshots, while the bundled renderer turns the same manifest into an editable workbook and a landscape PDF and checks that their IDs, counts, states, dates, and totals agree.

**Tech Stack:** Python 3.11, SQLite, MCP 2.x, pytest, openpyxl, HTML/CSS, headless Chrome or Chromium

**Spec:** `docs/superpowers/specs/2026-09-20-work-wbs-design.md`

## Global Constraints

- Keep baseline, forecast, and actual dates separate; an approved baseline is immutable.
- Never infer an unknown owner, date, effort, status, result, or approval to fill the layout.
- Preserve missing effort separately from verified zero effort.
- Keep tasks, zero-effort milestones, and unapproved additions separate in counts and totals.
- Generate XLSX and PDF from one validated manifest and refuse mismatched outputs.
- Store each WBS document version as a new schedule snapshot; never rewrite an earlier version.
- A WBS row or schedule date is not implementation authorization.
- Bundle all standard layout assets in the plugin so new users do not need the reference PDF.
- Do not add resource-capacity optimization, timesheets, billing calculations, Slack posting, branch creation, deployment, or production mutation.

def test_wbs_schedule_snapshots_preserve_versions_and_zero_effort(tmp_path: Path) -> None:
    store = make_store(tmp_path)

            "wbs_status": "진행 중", "schedule_basis": "confirmed",
